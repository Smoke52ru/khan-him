# Почта тестового контура (Selectel)

Пошаговое подключение **почтового сервиса Selectel** к домену
**smoke52.ru**, чтобы сайт на VPS отправлял письма о заявках.

Сервис уже заведён в панели Selectel для тестового деплоя. Эта
инструкция доводит его до рабочей отправки с `noreply@smoke52.ru`.
Домен сайта — в [`DOMAIN.md`](./DOMAIN.md). Как устроен Nodemailer в
приложении — в [`DEPLOY.md`](./DEPLOY.md), раздел про SMTP.

Документация Selectel:
[подключить почтовый сервис](https://docs.selectel.ru/email-service/connect-email-service/),
[ошибки SMTP](https://docs.selectel.ru/email-service/smtp-errors/).

## Что это за сервис

Почтовый сервис Selectel — исходящий SMTP. Приложение само почту не
принимает: контейнер `app` подключается к `smtp.mail.selcloud.ru` и
просит доставить письмо.

```
Форма на сайте
    → заявка в Postgres
    → src/lib/requestEmail.ts
    → Nodemailer (src/lib/email.ts, secure: false)
    → smtp.mail.selcloud.ru:1126
    → ящик получателя (Gmail, Яндекс, Mail.ru, …)
```

На VPS почтовый сервер не ставится. Порты 25, 465, 587 на сервер
открывать не нужно: соединение исходящее, на порт **1126** Selectel.

Сервис не создаёт ящики `@smoke52.ru` и не принимает входящую почту.
Адрес `noreply@smoke52.ru` — только подпись отправителя, ящика с таким
именем нет. Читать тестовые письма нужно на обычном ящике, который
указан получателем (`REQUESTS_FALLBACK_EMAIL` или «Адреса для заявок»
в админке).

К одному ресурсу Selectel можно привязать не больше трёх доменов.
Лимит отправки ресурса — **20 писем за пять минут** на все его домены.

Отправитель обязан быть на домене, привязанном к ресурсу. Для теста
это `smoke52.ru`. Письмо с `@khan-him.ru` или с чужого домена Selectel
отклоняет: `501 from domain not trusted`.

---

## 0. Где взять логин

1. Панель Selectel → верхнее меню **Продукты** → **Почтовый сервис**.
2. Если ресурса ещё нет: **Создать ресурс**, имя любое (на отправку
   не влияет, например `khan-him-test`) → **Создать**.
3. Откройте ресурс → вкладка **Информация**.

На этой вкладке:

- **Ключ проверки владения доменом** — значение первой TXT;
- логин и пароль SMTP (логин числовой, это не email);
- после привязки домена — карточка домена и строка **DKIM**.

Пароль в репозиторий и в этот файл не копируйте. Он живёт только в
`.env` на сервере.

---

## 1. TXT: домен ваш

Пока этой записи нет, домен к ресурсу не добавится.

Рег.ру → **Домены** → **smoke52.ru** → **DNS-серверы и управление
зоной** → **Изменить** → **Добавить запись**.

DNS-серверы зоны — `ns1.reg.ru` и `ns2.reg.ru`
(подробнее в [`DOMAIN.md`](./DOMAIN.md)).

| Поле | Значение |
|---|---|
| Тип | **TXT** |
| Subdomain | `@` |
| Text | ключ с вкладки **Информация**, как есть |

Ключ выглядит как UUID, например
`74f878e2-dia4-477a-ccc5-989f428173f9`. Кавычки вокруг значения в поле
Text не ставьте. Subdomain — `@`, не `smoke52.ru`: иначе имя
задублируется.

Подождите, пока запись видна снаружи (на DNS Рег.ру обычно
15 минут–час, Selectel закладывает до 72 часов):

```bash
dig +short TXT smoke52.ru
```

В ответе должна быть строка с ключом.

---

## 2. Привязать домен к ресурсу

1. **Почтовый сервис** → ваш ресурс → **Информация**.
2. Блок **Привязанные домены** → **Добавить**.
3. Имя: `smoke52.ru` (без `https://` и без слэша).
4. **Добавить**.

Если Selectel пишет, что владение не подтверждено — TXT ещё не
разошлась или Subdomain в Рег.ру не `@`. Повторите `dig` и шаг 1.

## 3. DKIM, DMARC, SPF

Три записи в той же зоне Рег.ру. В Subdomain — относительное имя,
без `.smoke52.ru` на конце.

### DKIM

Значение копируется из карточки домена: **Информация** → карточка
`smoke52.ru` → строка **DKIM**. Это длинная строка вида
`v=DKIM1; k=rsa; p=...`. Вставьте её целиком в одно поле Text.

| Поле | Значение |
|---|---|
| Тип | TXT |
| Subdomain | `selcloud._domainkey` |
| Text | строка DKIM из карточки домена |

Проверка:

```bash
dig +short TXT selcloud._domainkey.smoke52.ru
```

### DMARC

| Поле | Значение |
|---|---|
| Тип | TXT |
| Subdomain | `_dmarc` |
| Text | `v=DMARC1; p=quarantine;` |

Проверка:

```bash
dig +short TXT _dmarc.smoke52.ru
```

### SPF

У домена может быть только одна SPF (одна TXT, которая начинается
с `v=spf1`). Отдельная от ключа владения: на `@` две разные TXT —
это нормально.

| Поле | Значение |
|---|---|
| Тип | TXT |
| Subdomain | `@` |
| Text | `v=spf1 include:spf.mail.selcloud.ru ?all` |

Если SPF уже есть, не создавайте вторую: допишите в существующую
`include:spf.mail.selcloud.ru`.

Проверка:

```bash
dig +short TXT smoke52.ru
```

В выводе и ключ владения, и `v=spf1 include:spf.mail.selcloud.ru ?all`.

В карточке домена в Selectel статусы SPF, DKIM и DMARC обновляются
после распространения DNS. Пока домен не в списке доверенных,
отправка падает с `501 from domain not trusted`.

Обработка жалоб на спам (пересылка FBL Mail.ru на
`fbl@mail.selcloud.ru`) для теста не нужна: она про массовые
рассылки и требует отдельный ящик.

## 4. SMTP в `.env`

На сервере, `/opt/khan-him/.env`. Порт **1126**: в
`src/lib/email.ts` у транспорта `secure: false`, шифрование
поднимается через STARTTLS. Так Selectel описывает 1126
(«no SSL / STARTTLS»).

Порт **1127** (TLS сразу) и порт **465** с этим кодом не
используйте. Порт **587** — это Яндекс и Mail.ru, не Selectel.

```bash
SMTP_HOST=smtp.mail.selcloud.ru
SMTP_PORT=1126
SMTP_USER=логин-с-вкладки-Информация
SMTP_PASS=пароль-с-вкладки-Информация
SMTP_FROM="Хан-Хим <noreply@smoke52.ru>"
REQUESTS_FALLBACK_EMAIL=ваш-ящик@gmail.com
```

`SMTP_FROM` — любой адрес на `smoke52.ru`. Ящик заводить не нужно.
Имя в кавычках можно сменить; домен в адресе — нет.

`REQUESTS_FALLBACK_EMAIL` — живой ящик, который вы открываете сами.
Туда уходит `pnpm email:test`. Туда же уходит письмо с формы, если
в админке пуст список **Адреса для заявок**.

Подставьте переменные в уже запущенный контейнер (обычный
`docker restart` env не обновляет):

```bash
cd /opt/khan-him
docker compose -f docker-compose.vps.yml up -d --force-recreate app
```

Пока сайт ещё на стеке по IP, тот же `--force-recreate app` с
`-f docker-compose.vps-ip.yml`. Почта от режима HTTP/HTTPS не
зависит. От режима зависит только ссылка в письме: она берётся из
`SERVER_URL` ([`DOMAIN.md`](./DOMAIN.md)).

Проверьте, что внутри контейнера именно эти значения (пароль в
вывод `printenv` попадёт — не оставляйте его в общем логе):

```bash
docker compose -f docker-compose.vps.yml exec app printenv SMTP_HOST SMTP_PORT SMTP_FROM
```

С VPS порт Selectel должен открываться наружу:

```bash
timeout 5 bash -c 'cat < /dev/null > /dev/tcp/smtp.mail.selcloud.ru/1126' && echo ok
```

## 5. Куда уходят заявки с сайта

Два адресата, по очереди (`src/lib/requestEmail.ts`):

1. Глобал **Настройки сайта** → поле **Адреса для заявок**
   (`/admin` → Globals → Настройки сайта). Туда сид кладёт адрес из
   `REQUESTS_FALLBACK_EMAIL` на момент `pnpm seed`.
2. Если список пуст — `REQUESTS_FALLBACK_EMAIL` из `.env`.

Откройте список и оставьте ящик, который реально читаете. Иначе
форма будет слать на старый адрес из сида, а тест из скрипта — на
новый.

Если у посетителя заполнен email, он попадает в `Reply-To`.
Ошибка SMTP заявку не удаляет: запись уже в админке, сбой пишется
в лог `Failed to send request email`.

---

## 6. Проверка

1. Домен `smoke52.ru` есть в **Привязанных доменах**, статусы
   DNS в карточке без ошибки.
2. Тестовое письмо:

```bash
cd /opt/khan-him
docker compose -f docker-compose.vps.yml exec app pnpm email:test
```

Скрипт шлёт на `REQUESTS_FALLBACK_EMAIL`. Тема: «Тестовое письмо
Хан-Хим». Текст внутри упоминает Mailpit — на VPS Mailpit нет,
смотрите обычный ящик, включая спам.

3. Заявка с сайта: запись в `/admin` → Заявки, письмо на адрес из
   **Адреса для заявок**, ссылка в письме на
   `https://smoke52.ru/admin/collections/requests/...`
   (когда `SERVER_URL` уже доменный).

Логи, если письма нет:

```bash
docker compose -f docker-compose.vps.yml logs app | grep -iE 'mail|smtp'
```

## Ошибки SMTP Selectel

| Ответ сервера | Смысл |
|---|---|
| `501 from domain not trusted` | Домен в `SMTP_FROM` не привязан или владение не подтверждено. Нужен `smoke52.ru` в списке ресурса, TXT-ключ на `@` уже виден в DNS. |
| `550 bounced check filter` | Получатель в стоп-листе. При нескольких адресатах отправьте каждому отдельно. Адрес из локального стоп-листа можно убрать в панели ресурса. |
| `450 ratelimit exceeded` | Больше 20 писем за пять минут на ресурс. Подождите и повторите. |
| `421 SMTP command timeout` | Соединение простояло дольше 120 секунд. Повторите отправку. |
| Таймаут до приветствия SMTP | С VPS не открывается `smtp.mail.selcloud.ru:1126` (сеть или файрвол исходящих). |
| Письмо ушло, во входящих пусто | Смотрите спам. Проверьте, что DKIM и SPF из `dig` совпадают с таблицей выше. |

Частые промахи в `.env`: порт 1127 или 587, `SMTP_FROM` на чужом
домене, логин в виде email вместо числового логина с вкладки
**Информация**, правка `.env` без `--force-recreate app`.
