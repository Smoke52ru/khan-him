# Домен тестового контура (smoke52.ru)

Пошаговая привязка сайта на VPS Selectel к домену **smoke52.ru**
(регистратор Рег.ру). После настройки сайт открывается как
`https://smoke52.ru` с сертификатом Let's Encrypt.

Это домен разработчика для теста. Домен и почта заказчика — отдельный
вопрос, см. [`HOSTING.md`](./HOSTING.md).

Почта на этом же домене (SPF, DKIM, DMARC, SMTP) — в
[`MAIL.md`](./MAIL.md). Записи почты кладутся в ту же зону Рег.ру и
сайт не ломают.

Общий деплой сервера (Docker, Caddy, бэкап) — в [`DEPLOY.md`](./DEPLOY.md).

```
Браузер
   │  https://smoke52.ru
   ▼
DNS Рег.ру (ns1.reg.ru, ns2.reg.ru)
   │  A  @  →  публичный IPv4 VPS
   ▼
Selectel VPS :443
   │  Caddy, сертификат Let's Encrypt
   ▼
контейнер app :3000  (Next.js + Payload)
```

Сейчас тестовый сервер — публичный IPv4 **176.53.226.13**
(стек по IP, `docker-compose.vps-ip.yml`). Перед сохранением A-записи
сверьте адрес в панели Selectel: **Облачная платформа → Серверы →**
карточка сервера. Если сервер пересоздавали, в DNS нужен новый адрес.

Каталог проекта на сервере: `/opt/khan-him`.

---

## 0. DNS-серверы Рег.ру

Зону из этой инструкции видят только серверы Рег.ру
`ns1.reg.ru` и `ns2.reg.ru`. Для нового домена в Рег.ру они стоят
по умолчанию.

1. Личный кабинет Рег.ру → **Домены** → **smoke52.ru**.
2. Блок **DNS-серверы и управление зоной**.
3. В списке DNS должны быть `ns1.reg.ru` и `ns2.reg.ru`.

Если там другие серверы (хостинг Рег.ру, Selectel, свои), записи ниже
нужно создавать у того, кто реально отвечает за зону. Для теста
оставьте серверы Рег.ру и правьте зону в этом же блоке.

Свежий домен может ещё не резолвиться вообще: делегирование после
покупки занимает до 24 часов. Записи в панели можно создать сразу;
проверка `dig` заработает, когда NS появятся в интернете.

Официальная справка Рег.ру:
[настройка ресурсных записей](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-v-lichnom-kabinete),
[какие DNS прописать](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/kak-propisat-dns-dlya-domena-v-lichnom-kabinete-reg-ru).

## 1. A-запись на VPS

В том же блоке **DNS-серверы и управление зоной** нажмите **Изменить**,
затем **Добавить запись**.

| Поле в шторке | Значение |
|---|---|
| Тип | **A** |
| Subdomain | `@` |
| IP Address | публичный IPv4 VPS (`176.53.226.13`, если карточка сервера та же) |

**Готово.**

`@` — это корень `smoke52.ru`. Писать `smoke52.ru` в Subdomain не нужно:
Рег.ру допишет зону сам.

Если на `@` уже есть другая A-запись (парковка Рег.ру или чужой IP) —
удалите её. Две A с разными адресами открывают сайт через раз.

`www` не добавляйте. Caddy выпускает сертификат и отдаёт сайт только
для `DOMAIN` из `.env`, сейчас это корень. Имя `www.smoke52.ru` без
отдельного блока в `Caddyfile` сертификат не получит.

Обновление зоны на DNS Рег.ру — от 15 минут до часа. Если только что
меняли DNS-серверы домена — до 24 часов.

## 2. Проверить, что имя смотрит на сервер

На своей машине или на VPS (`apt install dnsutils`, если нет `dig`):

```bash
dig +short NS smoke52.ru
dig +short A smoke52.ru
```

Ожидание:

```
ns1.reg.ru.
ns2.reg.ru.
176.53.226.13
```

Пока A пустой или чужой, Caddy сертификат не получит. Подождите и
повторите `dig`. Сверьте IP с карточкой сервера в Selectel.

---

## 3. Открыть 80 и 443

В панели Selectel у сервера (файрвол / группа безопасности) входящие:

| Порт | Зачем |
|---|---|
| 22 | SSH, уже открыт |
| 80 | HTTP и проверка Let's Encrypt |
| 443 | HTTPS |

Порты 3000 и 5432 снаружи не открывать.

---

## 4. `.env` на сервере

Файл: `/opt/khan-him/.env`.

```bash
DOMAIN=smoke52.ru
SERVER_URL=https://smoke52.ru
```

Строго так:

- схема `https://`;
- без `:3000` и без слэша в конце;
- `DOMAIN` и хост в `SERVER_URL` совпадают.

`SERVER_URL` — адрес, который люди вводят в браузере. Из него
собираются ссылки в письмах и список CSRF для входа в `/admin`.
Значение `http://176.53.226.13` или `https://smoke52.ru:3000` после
перехода на домен снова сломает сессию админки.

Остальные переменные (секреты, Postgres, SMTP) не трогайте, кроме
почты по [`MAIL.md`](./MAIL.md). Пароли в git не коммитьте.

---

## 5. Переключить стек с IP на домен

На VPS, из `/opt/khan-him`. Том Postgres и `uploads` сохраняются:
`down` **без** `-v`.

Если сейчас запущен режим по IP:

```bash
cd /opt/khan-him
docker compose -f docker-compose.vps-ip.yml down
docker compose -f docker-compose.vps.yml up -d
docker compose -f docker-compose.vps.yml ps
docker compose -f docker-compose.vps.yml logs -f caddy
```

Если доменный стек ещё ни разу не собирали и образа `khan-him:latest`
нет, добавьте `--build` к `up`.

Caddy читает `Caddyfile`:

```
{$DOMAIN:localhost} {
	reverse_proxy app:3000
}
```

Сам слушает 80 и 443, проходит проверку Let's Encrypt, кладёт
сертификат в том `caddy-data` и дальше обновляет его. В логах не
должно быть ошибок ACME / TLS. Первое получение сертификата — обычно
в течение минуты после того, как A-запись уже указывает на этот IP.

Сайт: `https://smoke52.ru/`  
Админка: `https://smoke52.ru/admin`

---

## 6. Проверка

1. `dig +short A smoke52.ru` — IP сервера.
2. `https://smoke52.ru/` открывается, в браузере сертификат Let's Encrypt.
3. `http://smoke52.ru/` само уходит на `https://`.
4. `/admin` — вход и сохранение любой записи без ошибки прав.
5. `docker compose -f docker-compose.vps.yml exec app printenv SERVER_URL`
   печатает `https://smoke52.ru`.

Почту после этого проверьте по [`MAIL.md`](./MAIL.md): ссылка на заявку
в письме должна начинаться с `https://smoke52.ru`.

## Если что-то не так

| Симптом | Что сделать |
|---|---|
| `dig` пустой | NS ещё не делегированы или A не сохранилась. Подождите. В панели Рег.ру Subdomain должен быть `@`, не полное имя. |
| `dig` показывает не тот IP | В зоне две A-записи или в DNS попал старый адрес. Оставьте одну A на текущий IPv4 сервера. |
| Сайт по IP есть, по домену нет | Стек всё ещё `docker-compose.vps-ip.yml`, либо закрыт 443, либо A не на этот сервер. |
| В логах Caddy ошибка ACME | A ещё не на этот IP; закрыт порт 80; порт 80 занят другим процессом (старый контейнер не остановлен). |
| Сертификат «чужой» или имя не сходится | В `.env` `DOMAIN` не `smoke52.ru`, либо открываете `www`. |
| Логин в `/admin` сразу выкидывает | `SERVER_URL` не равен `https://smoke52.ru`. Правка `.env` попадает в процесс только через `docker compose -f docker-compose.vps.yml up -d --force-recreate app`. |
| Сохранение в админке: нет права | Тот же `SERVER_URL`: браузер шлёт `Origin: https://smoke52.ru`, и он должен быть в CSRF-списке. |

Логи:

```bash
docker compose -f docker-compose.vps.yml logs -f caddy
```

После правки `Caddyfile` или `DOMAIN`:

```bash
docker compose -f docker-compose.vps.yml up -d caddy
```

## Записи в зоне, когда подключена и почта

Сайт использует только A. Остальное добавляется по [`MAIL.md`](./MAIL.md)
и с сайтом не конфликтует. MX нет: почтовый сервис Selectel ящиков
на домене не держит.

| Subdomain | Тип | Зачем |
|---|---|---|
| `@` | A | сайт → IP VPS |
| `@` | TXT | ключ владения доменом для Selectel |
| `@` | TXT | SPF `v=spf1 include:spf.mail.selcloud.ru ?all` |
| `selcloud._domainkey` | TXT | DKIM, значение из карточки домена в Selectel |
| `_dmarc` | TXT | `v=DMARC1; p=quarantine;` |

Две TXT на `@` (ключ владения и SPF) — нормально. Вторая SPF — нет:
у домена одна SPF-запись.
