# wordpress-catalog Specification

## Purpose

Публичный каталог второй сборки: посетитель находит позицию среди сотен
товаров, смотрит характеристики и скачивает документы. Цен на сайте нет.

## Requirements

### Requirement: Список товаров каталога
Страница каталога SHALL показывать опубликованные товары карточками: фото,
название, альтернативные названия, фасовка, признак наличия и кнопка «В
запрос». По умолчанию товары отсортированы по названию по алфавиту.

#### Scenario: Открытие каталога
- **WHEN** посетитель открывает страницу каталога
- **THEN** он видит карточки опубликованных товаров, отсортированные по названию

#### Scenario: Товар без фото
- **WHEN** у товара нет ни одного фото
- **THEN** карточка показывает нейтральную заглушку вместо изображения

### Requirement: Видимость только опубликованных товаров
Публичный сайт MUST NOT показывать товары, снятые с публикации, ни в списке,
ни в поиске, ни по прямой ссылке.

#### Scenario: Снятый с публикации товар в списке
- **WHEN** товар снят с публикации в админке
- **THEN** он не появляется в каталоге и в результатах поиска

#### Scenario: Прямая ссылка на снятый товар
- **WHEN** посетитель открывает адрес карточки товара, снятого с публикации
- **THEN** сайт отвечает страницей «Не найдено» с кодом 404

### Requirement: Пагинация каталога
Каталог SHALL показывать не более 24 товаров на странице и давать перейти на
другие страницы. Номер страницы MUST отражаться в адресе.

#### Scenario: Переход на следующую страницу
- **GIVEN** в каталоге больше 24 опубликованных товаров
- **WHEN** посетитель переходит на вторую страницу
- **THEN** он видит следующие товары, а адрес содержит номер страницы

#### Scenario: Несуществующая страница
- **WHEN** посетитель открывает номер страницы больше последнего
- **THEN** сайт показывает пустой результат с предложением вернуться к началу каталога

### Requirement: Поиск по каталогу
Поиск SHALL находить товары по вхождению строки без учёта регистра в
названии, альтернативных названиях, химической формуле, номере CAS и артикуле.
Поисковый запрос MUST отражаться в адресе.

#### Scenario: Поиск по альтернативному названию
- **GIVEN** у товара «Натрий едкий» указано альтернативное название «каустик»
- **WHEN** посетитель ищет «Каустик»
- **THEN** товар «Натрий едкий» есть в результатах

#### Scenario: Поиск по формуле
- **WHEN** посетитель ищет «H3BO3»
- **THEN** в результатах есть товары с этой химической формулой

#### Scenario: Ничего не найдено
- **WHEN** по запросу нет ни одного опубликованного товара
- **THEN** сайт сообщает, что ничего не найдено, и предлагает оставить быструю заявку

### Requirement: Фильтры каталога
Каталог SHALL позволять фильтровать товары по категории и по наличию («на
складе» или «под заказ»). Фильтры MUST сочетаться между собой и с поиском и
отражаться в адресе.

#### Scenario: Фильтр по категории
- **WHEN** посетитель выбирает категорию
- **THEN** он видит только опубликованные товары этой категории

#### Scenario: Сочетание фильтров и поиска
- **WHEN** посетитель выбирает категорию, наличие «на складе» и вводит поисковый запрос
- **THEN** в результатах только товары, подходящие под все три условия

#### Scenario: Пустая категория скрыта
- **WHEN** в категории нет ни одного опубликованного товара
- **THEN** её нет в списке фильтров

### Requirement: Карточка товара
Карточка товара SHALL иметь постоянный читаемый адрес и показывать заполненные
поля: название, артикул, альтернативные названия, формулу, номер CAS, ГОСТ,
ТУ, фасовку, наличие, описание, применение, технические характеристики,
хранение, транспортировку, технику безопасности, галерею и документы.
Незаполненные поля MUST NOT показываться.

#### Scenario: Просмотр карточки
- **WHEN** посетитель открывает карточку товара из каталога
- **THEN** он видит все заполненные поля товара и галерею фото

#### Scenario: Пустое поле не показывается
- **WHEN** у товара не заполнен номер CAS
- **THEN** в карточке нет строки «Номер CAS»

### Requirement: Скачивание документов
Документы, прикреплённые к товару, SHALL быть доступны для скачивания любому
посетителю без входа. Для каждого документа MUST показываться его название,
формат и размер.

#### Scenario: Скачивание паспорта качества
- **GIVEN** к товару прикреплён PDF «Паспорт качества»
- **WHEN** посетитель нажимает на документ в карточке
- **THEN** файл скачивается или открывается в браузере без запроса логина

### Requirement: Похожие товары
Карточка товара SHALL показывать до 4 других опубликованных товаров из той же
категории в блоке «Смотрите также».

#### Scenario: Блок «Смотрите также»
- **GIVEN** в категории товара есть другие опубликованные товары
- **WHEN** посетитель открывает карточку
- **THEN** он видит до 4 таких товаров, текущий товар среди них не повторяется

### Requirement: Метаданные для поисковиков
Каждая карточка товара и страница каталога SHALL иметь осмысленные заголовок
и описание страницы. Сайт MUST отдавать карту сайта со всеми опубликованными
товарами.

#### Scenario: Заголовок карточки
- **WHEN** поисковый робот загружает карточку товара
- **THEN** заголовок страницы содержит название товара и слово «оптом»

#### Scenario: Карта сайта
- **WHEN** робот запрашивает карту сайта
- **THEN** в ней есть адреса всех опубликованных товаров и нет снятых с публикации
