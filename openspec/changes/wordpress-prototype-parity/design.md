# Design

## Context

См. proposal.md — Why. Вторая сборка уже работает в `wordpress/`; публичная
тема `khan-him` копирует токены и часть блоков прототипа, но шаблоны ещё
«черновые». Эталон композиции — `src/app/(frontend)/*` и
`src/components/*` (Tailwind-классы → ручной CSS в `assets/site.css`).

## Goals / Non-Goals

**Goals:**
- Совпадение публичных страниц WP с прототипом по блокам, иерархии и
  ключевым подписям/контролам.
- Один проход по теме: шапка → главная → карточка списка → деталка →
  каталог → статика → заявки.
- Проверка на 360 px и на демо-сиде без смены данных.

**Non-Goals:**
- Пиксель-перфект и полный перенос Tailwind runtime.
- Смена модели данных / админки / SMTP / антиспама.
- SPA-поведение форм (отправка без reload).
- Паритет админки Payload ↔ WP.

## Decisions

1. **Эталон — прототип, не текущий WP-спек «как есть»**  
   Где старый WP-спек расходился с прототипом (форма на главной), правим
   спек и UI под прототип.  
   Альтернатива: оставить форму на главной — отвергнуто (явный запрос
   паритета).

2. **Правки только в теме (+ точечно JS счётчика)**  
   Формула на карточке списка уже в meta — меняем `product-card.php`.
   Плагин не трогаем, если не всплывёт дыра.  
   Альтернатива: общий React/SSR — слишком тяжело для хостинга.

3. **CSS: расширять `assets/site.css`, не подключать Tailwind**  
   Добавить недостающие классы (`.btn-dark`, полосы главной, `dl`
   divide-y, карточки списка запроса). Bump `?ver=` для сброса кэша.  
   Альтернатива: скомпилированный Tailwind — лишняя сборка на PHP-хосте.

4. **Список запроса: карточки вместо `<table>`**  
   Разметка в `page.php` + `request-list.js` (рендер строк → карточки).  
   Альтернатива: стилизовать таблицу — хуже совпадает с прототипом.

5. **Порядок внедрения**  
   Shared chrome → `front-page.php` → `product-card.php` →
   `single-product.php` → `archive-product.php` → `page.php` ветки →
   визуальная сверка с прототипом (оба стека по очереди).

## Risks / Trade-offs

- [Расхождение копирайта мелких фраз] → Сверять строки с прототипом при
  правке шаблона; оферту выровнять с `OfferDisclaimer`.
- [Регрессия 360 px] → После правок шапки/таблиц повторить проверку
  overflow.
- [Оба стека на :3000] → Не поднимать вместе; сверку делать по очереди.

## Migration Plan

Локально: `docker compose down` у одного стека, `up` у другого. Боевой
деплой WP не меняется по схеме — только файлы темы. Откат — предыдущая
версия темы из git.
