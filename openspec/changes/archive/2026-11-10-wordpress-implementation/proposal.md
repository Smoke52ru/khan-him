# Proposal

## Why

Текущий сайт на Next.js и Payload работает только на VPS с Docker. Нужна
вторая сборка с тем же функционалом, которую можно поставить на виртуальный
хостинг с PHP и MySQL. Обе версии какое-то время живут рядом; какая станет
боевой, ещё не решено.

## What Changes

- Новая сборка в каталоге `wordpress/`: публичный сайт и админка на
  WordPress. Текущее приложение не меняется и не заменяется.
- Тот же функционал, что у прототипа: каталог с поиском и фильтрами,
  карточка, список запроса, три формы заявок, согласия по 152-ФЗ, антиспам,
  сохранение заявки и письмо, админка на одного пользователя, служебные
  страницы. Цен нет.
- Свои товары, заявки и файлы. Обмена данными с Postgres нет.
- Локальный запуск своим Compose. Одновременно с текущим стеком его не
  поднимают: перед стартом одного другой останавливают, порты не разводятся.
- Юридические страницы и «О компании» без пометки «черновик»: пустой текст
  в админке даёт на сайте только заголовок. Так записано в `PRODUCT.md` и
  сделано в текущем сайте. В спецификации `site-info` завершённого изменения
  `scaffold-prototype` ещё сказано про явный черновик — для этой сборки
  действует более позднее решение из `PRODUCT.md`.
- Демо-данные: 20–30 сгенерированных позиций. Данные ldhim не переносим.

Вне объёма: выбор боевой сборки и показ WordPress заказчику, приём боевых
заявок на второй сборке, перенос каталога из Payload, выключение Next.js,
покупка хостинга и домена, цены, склады, CRM, статьи, Яндекс Метрика.

## Capabilities

### New Capabilities

- `wordpress-catalog`: публичный каталог второй сборки — список, поиск,
  фильтры, пагинация, карточка, документы, похожие товары, только
  опубликованные позиции.
- `wordpress-catalog-admin`: ведение каталога в админке WordPress — один
  вход, товары, категории, фото и документы, публикация и удаление.
- `wordpress-requests`: заявки второй сборки — список запроса, три формы,
  проверки, согласия, антиспам, сохранение и письмо.
- `wordpress-site-info`: шапка, подвал, главная, контакты, реквизиты и
  юридические страницы второй сборки, настройки в админке.
- `wordpress-runtime`: отдельный локальный запуск и раскладка, пригодная
  для виртуального хостинга; стеки не работают одновременно.

### Modified Capabilities

Нет. В `openspec/specs/` возможностей нет. Поведение прототипа в
`scaffold-prototype` не меняется.

## Impact

- Новый каталог `wordpress/` (тема, плагин, Compose, сид). Кода там ещё нет.
- Корень репозитория, `src/`, Payload и деплой на Selectel не затрагиваются.
- Зависимости второй сборки: WordPress, PHP, MariaDB, почта через SMTP на
  локальный Mailpit. Платных плагинов нет.
- `PRODUCT.md` и `HOSTING.md` уже описывают две сборки; при появлении команд
  запуска их уточняет реализация, не этот план.
